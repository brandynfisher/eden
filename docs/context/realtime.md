# Realtime Voice Conversations

This document describes the `/realtime` route implementation for real-time voice conversations with Eden agents using ElevenLabs Conversational AI.

## Overview

The realtime feature enables live voice conversations between users and Eden agents. It uses ElevenLabs' Conversational AI platform for speech-to-text, LLM processing, and text-to-speech, while integrating with Eden's agent system for persona, memory, and session management.

**Route**: `/realtime/[agentId]`

## Architecture Flow

```
User (Microphone)
    ↓
Frontend (media-playground)
    ↓ WebSocket/WebRTC
ElevenLabs Conversational AI
    ↓ (uses dynamic variables for injecting eden agent context into system prompt)
Eden Session (stores messages passively after they are generated by Elevenlabs API)
```

## Configuration Options

### 1. ElevenLabs Agent Configuration

Located in `realtime-user-fields-config.ts`:

```typescript
interface AgentConfig {
  agent_id?: string        // ElevenLabs agent ID (overrides env var)
  firstMessage?: string    // Greeting message when conversation starts
  language?: string        // Language code (e.g., 'nl', 'en')
  prompt: PromptConfig     // LLM settings
  tts?: TTSConfig          // Text-to-speech settings
}
```

#### Current Hardcoded Values

```typescript
DEFAULT_AGENT_CONFIG = {
  agent: {
    firstMessage: 'Ik ben het Collectieve Brein van Broehaha...',
    language: 'nl',
    prompt: {
      llm: 'claude-sonnet-4-5',

      speed: 1.2,
      similarityBoost: 0.25,

```

Available LLM models (type `LLM`):
- `gpt-5`
- `gpt-5-mini`
- `gpt-5-nano`
- `gemini-2.5-flash-lite`
- `gemini-2.5-flash`
- `claude-sonnet-4-5`
- `claude-haiku-4-5`

### 3. TTS Configuration

```typescript
interface TTSConfig {
  voiceId?: string         // ElevenLabs voice ID
  stability?: number       // 0.0 to 1.0 (lower = more expressive)
  speed?: number           // 0.7 to 1.2
  similarityBoost?: number // 0.0 to 1.0
}
```

### 4. User Input Fields

Configurable user info fields collected before conversation:

```typescript
REALTIME_USER_FIELDS = ['name', 'email']
REALTIME_USER_FIELD_LABELS = { name: 'Name', email: 'Email' }
REALTIME_USER_FIELD_TYPES = { email: 'email' }
```

These fields are:
- Required in production mode
- Optional in dev mode (`?dev=true`)
- Saved to Eden session as first message
- Used to personalize first message greeting

## Dynamic Variables System

ElevenLabs agents use dynamic variables (recommended over overrides) to inject runtime data:

### Variables Sent to ElevenLabs

```typescript
interface DynamicVariables {
  agent_system_prompt: string  // Complete system prompt
  first_message: string        // Personalized greeting
}
```

### System Prompt Construction

The `agent_system_prompt` is built from:

```markdown
You are {agent.name}.

## Description
{agent.description}

## Persona
{agent.persona}

## User Memory
{userMemory from memory-context API}

## Collective Knowledge
{collectiveMemory shards from memory-context API}
```

### First Message Personalization

If user provides name: `"Heey {userName}! {baseFirstMessage}"`

## Session Management

### Session Creation

When conversation starts:
1. Frontend calls `/api/realtime/session/create`
2. Creates Eden session with `agent_ids: [agentId]`
3. If user info provided, saves as first passive message
4. Session ID stored in `sessionIdRef`

### Message Logging

During conversation:
- Both user and agent messages are saved via `/api/realtime/session/message`
- Messages are "passive" - they don't trigger agent responses (handled by ElevenLabs)
- Uses Fastify endpoint: `POST /v2/sessions/add-message`

## AgentRealtime Settings Model

A separate `AgentRealtime` collection stores per-agent realtime configuration:

```typescript
// apps/api/src/models/AgentRealtime.ts
interface AgentRealtimeSchema {
  agent: ObjectId               // Reference to agent (unique index)
  elevenlabs_agent_id?: string  // Override default ElevenLabs agent
  voice_id?: string             // ElevenLabs voice ID
  language?: string             // e.g., 'en', 'nl' (default: 'en')
  first_message?: string        // Custom greeting message
  llm_model?: RealtimeLLM       // LLM selection (default: 'claude-sonnet-4-5')
  temperature?: number          // 0-1 (default: 0.7)
  max_tokens?: number           // 1-16384 (default: 4096)
  tts_stability?: number        // 0-1 (default: 0.45)
  tts_speed?: number            // 0-1.2 (default: 1.0)
  tts_similarity_boost?: number // 0-1 (default: 0.25)
}
```

### API Endpoints

| Method | Route | Description |
|--------|-------|-------------|
| GET | `/v2/agents/:agentId/realtime` | Get agent's realtime settings (returns defaults if none exist) |
| PATCH | `/v2/agents/:agentId/realtime` | Update agent's realtime settings (upserts) |

Both endpoints require owner-level permissions on the agent.

### Frontend Integration

The settings are managed via a new "Realtime" tab in the agent settings modal:

| File | Purpose |
|------|---------|
| `apps/media-playground/features/sessions/views/AgentEditView/RealtimeTab.tsx` | Settings UI with sliders/selects for all options |
| `apps/media-playground/app/api/agents/[id]/realtime/route.ts` | Next.js API route proxy |

The tab appears only for users with owner access and has its own save button (independent of other agent settings)

## Voice Options

The `elevenLabsPlugin.ts` contains a list of 43 available ElevenLabs voices with metadata:
- `id`: ElevenLabs voice ID
- `name`: Display name
- `accent`: british, american, australian, etc.
- `age`: young, middle aged, old
- `gender`: male, female
- `description`: calm, raspy, deep, etc.

## Implementation Notes

### Microphone Access
Uses specific constraints to prevent Android telephony mode:
```typescript
{
  echoCancellation: false,
  noiseSuppression: false,
  autoGainControl: false,
  channelCount: 1,
  sampleRate: 48000,
  sampleSize: 16,
}
```

### Volume Monitoring
Real-time microphone input volume displayed using Web Audio API:
- Creates AudioContext + AnalyserNode
- Uses RMS calculation on time-domain data
- Updates via requestAnimationFrame

### Connection States
```typescript
type ConnectionStatus =
  | 'disconnected'
  | 'connecting'
  | 'connected'
  | 'disconnecting'
  | 'error'
```
